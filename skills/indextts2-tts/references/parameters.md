# `/tts` 参数参考

`POST /api/v1/tts`，`multipart/form-data`。下表是完整字段集（27 个），默认值取自服务端函数签名。

## 1. 必传

| 字段 | 类型 | 说明 |
|---|---|---|
| `text` | string | 合成文本。全空白 → 400；> 10000 字 → 413；> 2000 字只警告 |
| `spk_audio` | file | 音色参考音频。≤ 20 MB，wav/mp3/flac/ogg/m4a，**魔数嗅探**校验真实格式 |

## 2. 情感控制（四选一，由 `emo_mode` 决定）

| 字段 | 默认 | 说明 |
|---|---|---|
| `emo_mode` | `0` | `0`=跟随参考音频 / `1`=情感参考音频 / `2`=8 维向量 / `3`=情感描述文本 |
| `emo_audio` | — | **mode=1 必传**，情感参考音频文件 |
| `emo_weight` | `0.65` | 情感强度，映射到 `emo_alpha` |
| `vec1`…`vec8` | `0.0` | **mode=2 使用**，8 维情感向量 |
| `emo_text` | `""` | **mode=3 必传**，情感描述文本，≤ 500 字 |
| `use_random` | `false` | 情感随机化 |

### 四种模式的具体行为

| mode | 名称 | 实际发生什么 |
|---|---|---|
| `0` | 同参考音频 | 情感完全跟随 `spk_audio`。内部把 `emo_audio_prompt` 回退成 spk 音频，`emo_alpha` 强制 `1.0`，`emo_weight` **被忽略** |
| `1` | 情感参考音频 | `emo_audio` 提供情感，`emo_weight` 控制混合强度。缺 `emo_audio` → 400 |
| `2` | 8 维向量 | 见下方"向量归一化" |
| `3` | 情感描述文本 | `emo_text` 送 Qwen 情感模型分析出向量。**多一次 LLM 前向，多几秒**；Qwen 模型在首次用到时才加载 |

模式互斥：传了向量或文本时，服务端会忽略 `emo_audio`。**忽略是静默的**，不报错也不提示，
所以 `tts_client.py` 在参数与 `emo_mode` 不匹配时会打 `[warn] ... ignored`，看到就补上正确的 `--emo-mode`。

`emo_mode` 在表单里是**字符串**（`"0"`~`"3"`），服务端自己转 int；非数字或越界值返回 400，不会静默落成 0。

### 8 维向量顺序（固定）

```
[高兴, 愤怒, 悲伤, 害怕, 厌恶, 忧郁, 惊讶, 平静]
```

### 向量归一化（重要）

服务端在 `normalize_emo_vec` 里做两步处理，**调用方直接传 0~1 浮点即可，不要自己归一化**：

1. **bias 缩放**（`apply_bias=True`，默认开启），用来压低容易产生怪异结果的情绪：

   | 维度 | 高兴 | 愤怒 | 悲伤 | 害怕 | 厌恶 | 忧郁 | 惊讶 | 平静 |
   |---|---|---|---|---|---|---|---|---|
   | bias | 0.9375 | 0.875 | 1.0 | 1.0 | 0.9375 | 0.9375 | 0.6875 | 0.5625 |

2. **总和封顶**：bias 缩放后如果总和 > 0.8，整体等比缩到 0.8。

因此传 `惊讶=1.0` 实际只有 `0.6875`，传 `平静=1.0` 实际只有 `0.5625` —— 想强化这两维需要配合其它维度一起给。

## 3. 分段

| 字段 | 默认 | 说明 |
|---|---|---|
| `max_text_tokens_per_segment` | `120` | 每段 token 上限，控制自动分段粒度。服务端另有 20~600 的夹取区间 |
| `interval_silence` | `200` | 段间停顿（毫秒），服务端夹到 **10~500**。下限 10 而不是 0：完全不留停顿时多段会连成一串，听起来像漏气；上限 500 之外就不像停顿而像朗读课文了 |

长文本用 `POST /segments` 先预览分段结果（不合成），确认后再提交。

## 4. 采样参数

| 字段 | 默认 | 说明 |
|---|---|---|
| `do_sample` | `true` | GPT 采样开关。关掉会变确定性但明显更死板 |
| `top_p` | `0.8` | 核采样 |
| `top_k` | `30` | 截断候选数 |
| `temperature` | `0.8` | 温度，越高越随机 |
| `length_penalty` | `0.0` | 长度惩罚 |
| `num_beams` | `3` | beam 数，越大越慢越稳 |
| `repetition_penalty` | `10.0` | 重复惩罚。这个值偏高是 IndexTTS2 的正常设定，别按常见 LLM 习惯改到 1.1 |
| `max_mel_tokens` | `1500` | mel token 上限。**触顶会静默截断**，靠 `done` 事件的 `mel_capped` 才能发现 |

## 5. 输出与其他

| 字段 | 默认 | 说明 |
|---|---|---|
| `file_naming` | `title_time` | `title_time`=文本前 15 字+时间戳 / `title`=仅文本前 15 字 / `default`=时间戳+uuid |
| `client_id` | `""` | 调用方标识，仅用于日志区分，不影响生成 |

## 6. 调参建议

**想要更稳 / 更少幻觉**

- `do_sample=false`，或 `temperature` 降到 `0.6`~`0.7`
- `num_beams` 提到 `5`（代价：线性变慢）
- `repetition_penalty` 保持 `10.0` 附近，别乱动

**想要更有表现力**

- `temperature` 提到 `0.9`~`1.0`
- `top_p` 提到 `0.9`
- 配合 `emo_weight` 或情感向量

**音频被截断（`mel_capped=true`）**

1. 首选：把文本切短（用 `/segments` 看分段）
2. 次选：`max_mel_tokens` 提到 `2000`~`3000`（显存换长度，长文本会显著吃显存）

**多段之间太赶 / 太拖**

- 调 `interval_silence`：`120` 更紧凑，`300` 更从容
- 注意它只影响**段间**，不影响段内语速；段内语速要用 `/audio/tempo`

**整体语速不对**

- 合成完再调：`POST /audio/tempo`，`rate` 0.5~2.0，保音高
- 不要指望 `length_penalty` 调语速，它的效果不线性也不直观

**读音不对（多音字、专有名词）**

- 用术语表：`POST /glossary` 加 `term` + `reading_zh` / `reading_en`
- **长词优先**：内部按词条长度降序匹配，所以 `PCIe 5.0` 会先于 `PCIe` 命中
- **边界策略只作用于纯 ASCII 词条**：前后不能是 `\w` 或 `+`，避免 `TTS` 命中 `ATTS`、`C` 命中 `C++` 里的 C。含中文的词条**不加边界**（中文没有词边界，加了会让"人工智能"匹配不到"人工智能技术"）
- **默认 `cascade=false`**：每条术语只作用于原文，替换结果用私有区占位符暂存，不会被后续词条再改写一次。否则 `{"C++": "C 加加", "C": "西"}` 会把「他主要写 C++」变成「他主要写西加加」，静默出错
- 确实需要连锁替换时才开 `cascade=true`

## 7. 一个完整的 curl 示例

```bash
curl -N -X POST http://127.0.0.1:7860/api/v1/tts \
  -F "spk_audio=@examples/voice_01.wav" \
  -F "text=你好，这是一段测试语音。" \
  -F "emo_mode=2" \
  -F "vec1=0.4" -F "vec3=0.2" \
  -F "interval_silence=200" \
  -F "file_naming=title_time"
```

`-N` 关掉 curl 的输出缓冲，否则 SSE 会被攒着一次性吐出来，看不到进度。
