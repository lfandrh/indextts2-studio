## 2. 测试方法

- 每次生成走真实 `POST /api/v1/tts`（multipart + SSE），不使用 mock；记录服务端 `elapsed`、HTTP 状态、SSE 事件与产物 WAV。
- 显存/GPU 利用率通过 `nvidia-smi --query-gpu=memory.used,utilization.gpu` 每 **0.25s** 采样一次，记录生成前、峰值、生成后。
- 脚本每次启动会先 `POST /model/unload` 再套用目标配置，因此每个脚本会话的第一次请求包含 **9–16s 模型加载**；`加载s` 从 `server.log` 的加载区间解析并扣除，`RTF = 净生成s / 音频秒`。
- 音频时长由产物 WAV 头读取；服务端 `elapsed` 从任务入队开始计。
- 按显存从低到高排序执行：先 batch=0 的短/中/长文与情感模式，再 batch=2，最后 batch=12 高负载；高负载放最后。
- 所有其它生成参数保持 API 默认：`emo_weight=0.65`、`temperature=0.8`、`top_p=0.8`、`top_k=30`、`num_beams=3`、`repetition_penalty=10`、`max_mel_tokens=1500`、`interval_silence=200ms`、`do_sample=true`、`use_random=false`；分段 token 默认 120（仅 `seg60_500` 用 60）。
- 测试后已把 `model_config.json` 恢复为 `gpt_batch_size=0`、`diffusion_steps=25` 并卸载模型，服务停止，显存回落至 428 MiB。

## 4. 结论

- **23 次生成全部成功**（21 个场景，3 候选组额外 2 次），0 失败、0 OOM。
- **冷加载**：首次 16.0s，后续脚本会话重组模型 9–14s；热态生成不计加载。
- **batch=0**：RTF 从 0.93（20 字热态）降到 0.78–0.87（500–1500 字）；1500 字的 0.87 与 1000 字的 0.81 差异在单次测量噪声内。
- **batch=2 是默认档里收益最大的一档**：500 字 0.59 vs 0.83（快 29%），1000 字 0.54 vs 0.81（快 33%），3000 字 0.50；峰值约 7.0GB。
- **batch=12 不再更快**：500 字 0.63（batch2 为 0.59）、1000 字 0.63（batch2 为 0.54），峰值到 8009 MiB，只剩 183 MiB 余量，不适合作为默认。
- **50 步比 25 步慢约 20%**（同 500 字 batch2：0.71 vs 0.59），显存基本不变。
- **三种情感模式耗时接近**（200 字 RTF 0.87–0.95）；情感描述模式临时拉起 Qwen，实测多占约 0.9GB。
- **多候选不增加显存**：3 候选串行各约 46s，峰值与单候选持平。
- **参考音频 40s 比 1s 慢**（200 字净生成 53.6s vs 37.3s）；两条产物的音频时长不同，RTF 仅作同口径参考。
- **未触发 OOM**：最高峰值 8009/8192 MiB（batch12 500 字），仍差 183 MiB；没有人为用外部进程挤占显存去制造溢出。名为 `oom_*` 的三个场景是“探边界”场景，均成功。

## 5. 口径与限制

- 显存是 **全卡口径**，包含桌面/浏览器/Ming-3.0 服务；Windows WDDM 下 `nvidia-smi` 的单进程显存显示为 N/A，无法拆分。
- 早期 batch0 行峰值偏高（约 7.9GB）是因为 Ming-3.0 还在占用；它释放后，同配置峰值降到 5.8–7.9GB。因此这些数字**不能当作纯模型占用**，应在同一时间窗内横向比较。
- 0.25s 采样可能漏掉更短的瞬时尖峰；峰值是“观测到的最大值”，不是理论最大值。
- 单次测量噪声约 ±10~15%；长文本更容易受系统调度影响，结论看档位差异，不要抠单点小数。
- RTF 只反映速度，不代表音质；不同参考音频的语速不同，同样字数会产出不同音频时长。
- 文稿是同一段中文反复拼接，只用于压时长与段数，不代表多语种/生僻字/数字规范化的表现。
- `batch=12` 虽成功，但只剩 183 MiB 余量；同机再开其它 GPU 任务就可能 OOM，生产默认仍应是 0 或 2。

### 6.2 派生规则

所有字数场景都由基础文稿循环拼接、截到目标字数；若截断处不是句末标点，则把最后一个字符替换为 `。`，保证长度不变且以句号结尾。

```python
def text_of(n: int) -> str:
    s = (BASE_TEXT * (n // len(BASE_TEXT) + 1))[:n]
    return s if s.endswith(("。", "！", "？")) else s[:-1] + "。"
```

使用过的目标字数：**20、200、300、500、1000、1500、3000**（300 字用于 3 候选组；200 字用于三种情感模式与两组参考音频）。

<仓库根>/.venv/Scripts/python.exe server.py --port 7861

# 2) 另开一个终端，在仓库根目录执行；跑全量 23 次（高负载在最后）
